# fat16tool — FAT16 镜像原位文件替换（带崩溃恢复）

维护工具：在不重新打包整个卷的前提下，替换 FAT16 镜像中的一个已有文件。
修改按扇区原位进行，由旁置（sidecar）扇区日志协调，崩溃恢复后镜像只会
呈现**完整的旧文件**或**完整的新文件**。

## 镜像假设（修改前逐一核对）

- 无分区表，镜像直接以 FAT 引导扇区开头
- 每扇区 512 字节、恰好两份 FAT、簇数在 FAT16 范围内（4085–65524）
- 两份 FAT 完全一致；所有活跃簇链无环、无越界、无交叉占用，
  否则拒绝修改（退出码 2），镜像保持不变
- 按 8.3 短名路径定位文件（如 `/DIR/FILE.TXT`）；长名（LFN）目录项
  原字节保留，但不提供长名寻址

## 用法

```sh
python3 fat16tool.py check   IMAGE                 # 校验布局/FAT/簇链
python3 fat16tool.py replace IMAGE /DIR/FILE.TXT --file new.bin
python3 fat16tool.py replace IMAGE FILE.TXT --stdin < new.bin
python3 fat16tool.py replace IMAGE FILE.TXT --text "hello"
python3 fat16tool.py recover IMAGE                 # 恢复被中断的替换
```

退出码：0 成功；1 I/O 错误；2 镜像损坏拒绝修改；3 空闲簇不足（镜像不变）；
4 路径未找到或不是合法 8.3 名。

## 替换策略

- 复用文件原有簇链作为前缀；增长时空闲簇**按编号从小到大**分配，
  缩短时尾部簇释放为空闲；不足时镜像保持不变
- 目录项的位置、名称、属性、时间戳不变，仅更新起始簇与文件长度
- 只有内容真正变化的扇区会被写入（数据扇区、两份 FAT 中受影响的
  扇区、目录项所在扇区），其他文件与区域字节级不变

## 日志协议与崩溃模型

一次替换的全部扇区写入（文件数据 + 两份 FAT + 携带新长度的目录项）
先整体写入旁置日志 `IMAGE.journal`：

```
扇区 0      提交头（最后写）：magic、版本、状态、条目数、表扇区数、
            镜像扇区数、crc32(正文)、crc32(头前32字节)
扇区 1..T   表：每个条目一个 u32 镜像扇区号
扇区 T+1..  负载：各条目对应的新 512 字节内容
```

提交流程：写正文并逐扇区 fsync → 目录 fsync → 单扇区提交头 + fsync
（提交点）→ 按表回放进镜像（逐扇区 fsync）→ 删除日志。恢复时：
日志无效/未提交 → 丢弃（镜像从未被触碰，仍是旧版本）；日志已提交 →
幂等回放后删除日志（新版本）。恢复本身被中断可再次执行 `recover`。

崩溃模型：存储只能撕裂（半写）最近一次发出的扇区写；已被 fsync
确认的扇区是持久的。测试通过环境变量 `FAT16_CRASH_AT=<边界>` 在
每个持久化边界（`journal-create`、`journal-sector:<k>`、`journal-data`、
`journal-commit`、`image:<k>`、`image`、`journal-clear`）以 SIGKILL
终止进程。

## 测试

```sh
python3 test_fat16tool.py
```

测试自带**独立的**镜像构建器与读取器（直接按 FAT16 规范编写，与工具
实现零共享代码），覆盖：增长/缩短/置空/空文件写入/同尺寸、子目录、
LFN 保留、空间不足、四类损坏镜像拒绝、spc=4 镜像，以及崩溃矩阵——
在每个日志/镜像持久化边界终止进程并注入半写扇区，恢复后逐字节断言
镜像只能是旧版或新版、两份 FAT 一致、无失联簇、未修改区域不变，
并打印每个场景实际恢复的版本与涉及的扇区。
